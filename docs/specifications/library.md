# BashStockライブラリ仕様

この文書は、BashStockの実行環境、読み込み、関数名、入出力、終了状態を定義します。

## 対応する実行環境

配布物の公開APIは次の環境で動作します。
関数ごとの外部コマンドは、呼び出された関数が実行前に確認します。

| 対象 | 対応範囲 |
| --- | --- |
| シェル | Bash 3.2以上 |
| OS | macOS、Ubuntu、Fedora |

## 読み込み

利用者は配布物の`bashstock.sh`を`source`します。
読み込み処理は、公開関数と内部関数の定義、実行中のOSに対応するプロバイダーの選択、Tab補完の登録を実行します。

同じシェルで2回目以降に読み込んだ場合は、最初に定義した関数と補完を保持して終了状態0を返します。

## 公開関数の名前空間

公開関数は`domain::action`または`domain::category::action`のどちらかで命名します。
名前空間の各要素と関数名には小文字の`kebab-case`を使用します。

`domain`は、関数が主に扱う値、資源、または機能を単数形の名詞で表します。
`action`は、処理を表す動詞句、述語、または取得する値を表す名詞句です。

`category`は、`domain`が所有する下位概念に独自の操作や値があり、その下位概念を示さないと関数名の意味が失われる場合に使用します。
関数の個数だけを基準に階層を増やさず、同じ下位概念に属する公開関数へ同じ`category`を使用します。

| 関数 | 区切り方 |
| --- | --- |
| `string::upper` | 文字列そのものを変換するため、`string`の直下に置きます。 |
| `path::config-home` | パスとして返す一つの値を表すため、`path`の直下に置きます。 |
| `git::commit::edit-via-rebase` | Gitが所有するコミットを操作し、ブランチ、差分、stashとは異なる語彙を持つため、`commit`を下位概念にします。 |
| `arg::completion::dispatch` | 引数処理が所有する補完機構を操作するため、`completion`を下位概念にします。 |

### 関数名

| 種類 | 規則 | 例 |
| --- | --- | --- |
| 値の取得 | `get-`を付けず、値を表す名詞句を使用します。 | `system::host-name` |
| 状態の述語 | `is-`で始め、終了状態で真偽を返します。 | `path::is-directory` |
| 存在の述語 | `exists`を使用します。 | `command::exists` |
| 関係の述語 | 関係を表す動詞を使用します。 | `array::contains` |
| 変換 | 動詞を先頭に置きます。 | `string::encode-url` |
| 数量 | 要素数と文字数には`length`、バイト数には`byte-length`を使用します。 | `string::byte-length` |
| 複数結果 | 複数形を使用します。 | `regex::capture-groups` |
| 単位 | 単位を省略せず複数形で記載します。 | `time::unix-milliseconds` |

## 内部関数

Bashには関数の可視性を制限する仕組みがないため、内部関数は最後の要素を`_`で始めます。
公開関数へ従属する内部関数は、公開関数と同じ名前空間に置き、`_<公開関数のaction>-<役割>`と命名します。

| 用途 | 公開関数 | 内部関数 |
| --- | --- | --- |
| 名前付き引数の補完 | `user::create` | `user::_create-args` |
| 下位名前空間にある関数の補完 | `git::commit::edit-via-rebase` | `git::commit::_edit-via-rebase-args` |
| 一つの公開関数に従属する検査 | `file::replace-text` | `file::_replace-text-validate` |
| 名前空間内で共有する検査 | 対象外 | `file::_validate-regular-file` |

内部関数は公開APIの互換性保証に含めません。

## Docコメント

`src/`と`libexec/`の関数は、関数定義の直前に英語の`###`Docコメントを持ちます。
コメントは処理の責務、引数、標準出力、終了状態のうち、その関数を呼び出すために必要な情報を記載します。

## 入出力

値を返す関数は、結果だけを標準出力へ書きます。
述語関数は、条件が成立すると終了状態0、成立しないと終了状態1を返し、出力を書きません。
利用者が対処できる診断は標準エラー出力へ書きます。

公開関数は`exit`を呼び出さず、呼び出し元が後続処理を選べるように終了状態を返します。

## 終了状態

| 終了状態 | 意味 |
| ---: | --- |
| `0` | 処理に成功したか、述語の条件が成立しました。 |
| `1` | 述語の条件が成立しないか、検索対象が見つかりません。 |
| `64` | 引数の個数、形式、組み合わせが不正です。 |
| `66` | 入力ファイルまたは必要な入力元を利用できません。 |
| `69` | 必要なコマンド、モジュール、実行環境を利用できません。 |
| `73` | 利用者などの対象を作成できません。 |
| `74` | 入出力または状態の復元に失敗しました。 |
| `75` | 一時的な外部処理または待機が完了しません。 |
| `77` | 必要な権限を取得できません。 |

## 正規表現

正規表現を受け取る関数は、評価方式と評価範囲を関数の契約として定義します。

| 関数 | 正規表現 | 評価範囲 |
| --- | --- | --- |
| `regex::is-match` | Bashの`[[ =~ ]]`が解釈するPOSIX拡張正規表現 | 入力文字列 |
| `regex::capture-group` | Bashの`[[ =~ ]]`が解釈するPOSIX拡張正規表現 | 入力文字列 |
| `regex::capture-groups` | Bashの`[[ =~ ]]`が解釈するPOSIX拡張正規表現 | 入力文字列 |
| `file::contains-match` | Perlの`qr//`が解釈する正規表現 | ファイルの各行 |
| `file::replace-text` | Perlの`qr//`が解釈する正規表現 | 各行の最初の一致 |
| `file::replace-text-as-root` | Perlの`qr//`が解釈する正規表現 | 各行の最初の一致 |
| `file::replace-text-in-files` | Perlの`qr//`が解釈する正規表現 | 各ファイルの各行にある最初の一致 |
| `file::replace-text-in-files-as-root` | Perlの`qr//`が解釈する正規表現 | 各ファイルの各行にある最初の一致 |
| `file::replace-or-append-text` | Perlの`qr//`が解釈する正規表現 | 各行の最初の一致 |
| `file::replace-or-append-text-as-root` | Perlの`qr//`が解釈する正規表現 | 各行の最初の一致 |

ファイル置換関数は置換値をリテラル文字列として扱います。

## シェル状態

公開関数は、グローバル変数、現在のディレクトリ、`IFS`、ロケール、シェルオプション、呼び出し元の`BASH_REMATCH`を呼び出し前の状態に保ちます。
一時的な設定は関数のローカル変数またはサブシェルへ閉じ込めます。

Tab補完の登録は、ライブラリの読み込み時に実行します。

## ファイル更新と権限

通常権限と管理者権限のどちらでも実行できる操作では、管理者権限を使う公開関数を`-as-root`で終わる名前にします。
管理者権限を使う関数は、`command::run-as-root`から配布物内の`libexec/bashstock-root`を実行します。

ファイル更新関数は通常ファイルを同じディレクトリの一時ファイルで置き換え、所有者、グループ、モード、ACL、拡張属性を保持します。
複数ファイルを更新する関数は、すべての入力を検査してから更新を開始し、途中で失敗した場合は保存した内容を復元します。

## OS別処理

`platform`名前空間は、macOS、Ubuntu、Fedoraで同じ内部関数を定義します。
公開関数はOS固有コマンドを直接呼び出さず、`platform`の内部関数を通して実行します。

時間関数はPerlの`Time::HiRes`と`POSIX`を使用し、単調時計、起動後時計、Unix時刻、UTC日時、UTCオフセット付きローカル日時を同じ形式で返します。
